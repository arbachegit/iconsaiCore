O que eu erreiregistrado, não omitido

O middleware ainda usava a entrada externa obsoleta

A variável SKILLS_TOOLS_ENTRY_URL apontava para iconsai.ai/icon/tools, que retornava 404 após o redirect. O efeito medido era o erro reportado ao clicar em Ferramentas.

Método adotado: listar variáveis de produção com gh variable list --env production, corrigir a variável e rerodar o deploy; a prova final foi HTTP 307 para tools.iconsai.ai/admin e HTTP 200 no destino.

Erros do background do Chrome foram confundidos com a aplicação

FrameDoesNotExistError, strURL is not defined e Unchecked runtime.lastError vieram de chrome-extension://.../background.js, não do bundle Skills.

Método adotado: separar erros de extensão dos requests da aplicação e validar o deploy via build-info.txt, MIME dos assets e headers públicos.

Build local encontrou o snapshot remoto indisponível

Durante a geração estática, a API GitHub respondeu 404 para contents/skills e o aplicativo usou o fallback versionado. Isso não impediu a publicação nem alterou o contrato da tela.

Método adotado: aceitar o fallback já previsto, confirmar os cinco gates e repetir a prova no CI, que publicou e verificou os assets.

Os 401 de OTP não pertencem ao catálogo Skills

Os requests api/access/otp/start e verify retornaram 401 por ausência de sessão/token válido. O fluxo de autenticação está fora do escopo da reformulação das páginas internas.

Método adotado: manter o diagnóstico separado da UI e não mascarar o 401 com fallback visual.
